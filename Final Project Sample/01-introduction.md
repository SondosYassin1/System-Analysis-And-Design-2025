# 1. Introduction

## 1.1 Project Overview

Educational institutions with 200–1,000 students commonly rely on paper-based records, disconnected spreadsheets, and manual communication channels. This results in administrative inefficiency, delayed parent communication, error-prone grade calculations, and limited visibility into student performance.

The **School Management System (SMS)** is a web-based application designed to digitize and streamline core school operations — including student enrollment, attendance tracking, assignment management, grading, and parent communication — into a single, integrated platform.

## 1.2 Problem Statement

A typical 500-student school loses an estimated $116,000 annually to manual processes:

| Cost Area | Annual Impact |
|-----------|--------------|
| Administrative staff time | $45,000 |
| Teacher non-teaching time | $35,000 |
| Parent inquiry management | $12,000 |
| Paper and printing | $8,000 |
| Compliance and audit prep | $10,000 |
| Data entry errors and rework | $6,000 |

Beyond financial costs, the current state creates poor stakeholder experience: parents learn about issues only at report card time, teachers spend more time on paperwork than instruction, and administrators lack real-time data for decision-making.

## 1.3 Project Scope

**In Scope (Version 1.0):**
- User account management (students, teachers, parents, admins)
- Course and class management
- Student enrollment
- Attendance tracking
- Assignment creation, submission, and grading
- Grade calculation and report cards
- Parent progress monitoring
- Basic reporting and dashboards

**Out of Scope:**
- Cafeteria or transportation management
- AI-powered tutoring or analytics
- Financial/billing systems
- Social features (forums, messaging beyond notifications)
- Mobile native apps (responsive web only for v1.0)

## 1.4 Project Objectives

| # | Objective | Success Metric |
|---|-----------|----------------|
| 1 | Reduce administrative workload | 60% reduction in manual record-keeping time |
| 2 | Improve parent visibility | Parents can access grades within 24 hours of recording |
| 3 | Increase data accuracy | 99.5% accuracy in grade calculations |
| 4 | Enable anytime access | 24/7 availability via web browser |
| 5 | Deliver on schedule | Complete deployment in 16 weeks |

## 1.5 Methodology

This project follows **Agile (Scrum)** with 2-week sprints. The rationale:

- Requirements will evolve as stakeholders interact with early versions
- Teachers and administrators need to validate features incrementally
- Small cross-functional team (5–7 members) fits Scrum well
- Iterative delivery reduces risk of building the wrong thing
