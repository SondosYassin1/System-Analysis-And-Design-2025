# 13. Appendices

## Appendix A: Glossary

| Term | Definition |
|------|-----------|
| Actor | An external entity (person or system) that interacts with the system. |
| Agile/Scrum | Iterative development methodology using fixed-length sprints and continuous feedback. |
| API | Application Programming Interface — a set of rules for how software components communicate. |
| bcrypt | A password hashing algorithm designed to be computationally expensive to resist brute-force attacks. |
| CRUD | Create, Read, Update, Delete — the four basic operations on data. |
| ER Diagram | Entity-Relationship Diagram — a visual model of database entities and their relationships. |
| FERPA | Family Educational Rights and Privacy Act — U.S. law protecting student education records. |
| JWT | JSON Web Token — a compact, stateless token used for authentication. |
| MoSCoW | Prioritization method: Must have, Should have, Could have, Won't have. |
| NFR | Non-Functional Requirement — a quality attribute like performance, security, or usability. |
| REST | Representational State Transfer — an architectural style for designing web APIs. |
| SPA | Single Page Application — a web app that loads a single HTML page and dynamically updates content. |
| SRS | Software Requirements Specification — a document describing what a system should do. |
| Three-Tier | An architecture pattern separating presentation, business logic, and data storage layers. |
| UML | Unified Modeling Language — a standardized set of diagram types for modeling software systems. |
| Use Case | A description of how an actor achieves a specific goal using the system. |
| WCAG | Web Content Accessibility Guidelines — standards for making web content accessible. |
